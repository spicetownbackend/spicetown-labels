# 🌶️ Spice Town Grocery — Label Printing System

Retail label printing for Spice Town Grocery: staff scan a product barcode on
any phone, pick copies/variant, and a price label prints on the store's
Brother QL-810W. Prices flow in from Toast POS automatically, price changes
land in a review queue instead of auto-printing, and everything runs on
**$0/month hosting**.

## 🚀 The production system (live)

```
 Toast POS ──GH Actions sync (best-effort ~30 min)──▶ GitHub
                                                          │ products.csv +
                                                          │ price_changes.json
                                                          │ committed
                                                          ▼
                                          push → Render auto-deploy
                                                          │
                                                          ▼
 staff phone ──scan/search──▶ Render free tier (Flask app, remote print mode)
      │                              │  /api/print → PrintJob queued
      │                              │  price change → PriceHistory review row
      └──price-change review──────────┘
                                       ▼
 store tablet (Termux print bridge) ──raster over WiFi:9100──▶ Brother QL-810W
```

| Piece | Where | Notes |
|-------|-------|-------|
| Web app + API | Render free tier | Auto-deploys from `main`; SQLite on **ephemeral** disk (`/tmp`), rebuilt from `data/products.csv` on every boot |
| Catalog sync | GitHub Action `.github/workflows/toast-sync.yml` | Cron `*/30 * * * *`, but GitHub only *best-effort* honors schedule intervals — actual gaps run ~1–4 hours under normal load, not a bug in this repo (see `scripts/toast_sync.py`) |
| Price-change review | `data/price_changes.json` (committed alongside the catalog) → `PriceHistory` table | Staff review and print/dismiss from the scanner UI; nothing auto-prints |
| Print bridge | Store-side device (Termux on a tablet, or any always-on box on the store WiFi) | `scripts/print_bridge.py`, stdlib-only; polls the cloud queue and drives the printer; see `docs/BRIDGE.md` |
| Printer | Brother QL-810W on store WiFi | Receives server-rendered raster from the bridge over port 9100 |
| Secrets | GitHub Actions Secrets (Toast creds) + Render env (`STL_BRIDGE_TOKEN`, `STL_SECRET_KEY`) | Never committed to the repo |

Key behaviours:
- **Shared barcodes** are supported (same UPC on "XYZ" and "XYZ B1G1" → staff
  pick from a list); logical product identity is `(upc, name)`.
- **Street Kitchen / Catering / autogenerated-placeholder Toast menus are
  excluded entirely** — never synced into the catalog, never printed, never
  shown as a price change (`EXCLUDED_MENUS` in `scripts/toast_sync.py`). Retail
  counter menus (Halal Meat, Fish Market, Container, Produce, Fresh Flowers)
  stay in.
- **Price changes never auto-print.** A Toast sync that moves a price adds it
  to a review queue; staff print a fresh label or dismiss it from the
  scanner UI's "price change" banner.
- **Print history** is browsable in the UI (manual scans and price-change
  prints both), with one-tap reprint of any past job.
- Label names **never truncate** when shrinking or two-line wrapping can fit
  them; print jobs queue in the cloud when the bridge is offline and drain on
  reconnect; stuck jobs auto-requeue.

## Stack

- **Backend:** Flask + SQLAlchemy (SQLite)
- **Printing:** transports for CUPS / `brother_ql` / file / null, plus a
  decoupled remote print bridge for cloud hosting
- **Scanning:** QuaggaJS mobile camera + fuzzy name/UPC search (rapidfuzz)
- **Labels:** PIL/Pillow image generation (variants, barcode, auto-fit names)
- **Catalog source:** Toast POS Menus API (`ToastDataProvider`) synced to a
  committed CSV by a scheduled GitHub Action; the app itself reads the
  simple `file` provider and never needs Toast credentials at runtime
- **Tests:** 137 passing (`pytest -q`)

## How the pieces fit together

### 1. Catalog sync (Toast → GitHub → Render)

`scripts/toast_sync.py` runs on the schedule in `.github/workflows/toast-sync.yml`
(cron `*/30 * * * *` — GitHub Actions only *best-effort* honors short cron
intervals, so real-world gaps run 1–4 hours). Each run:

1. Reads the **current** `data/products.csv` for old prices, keyed by `(upc, name)`.
2. Pulls the live catalog from Toast (`ToastDataProvider.fetch_all()`).
3. Drops items from excluded menus (`EXCLUDED_MENUS`, substring-matched —
   Street Kitchen, Catering, the Toast autogenerated placeholder) before they
   ever become a row — they never enter the catalog, never print, never
   appear as a price change.
4. Skips exact `(upc, name)` duplicates within the same feed (keep first).
5. Preserves any hand-set `sale_price`/`clearance` override already in the CSV.
6. Diffs new vs. old prices (`_PRICE_EPSILON = 0.005`) and writes **both**
   `data/products.csv` (new prices) and `data/price_changes.json` (just this
   run's diffs — a full overwrite, not an accumulating log).

The workflow commits both files only if the catalog actually changed, which
triggers Render's auto-deploy. `--list-menus` is an audit-only mode
(`workflow_dispatch` input) that prints every live Toast menu name + item
count without touching the catalog — useful for confirming exclusion rules
against Toast's actual menu names.

### 2. Price-change review (not silent auto-print)

Render's free tier has no persistent disk, so the SQLite DB is wiped on every
redeploy — which happens right after every sync that changes prices. That
means an in-app "compare old vs. new price on upsert" never sees an old price
to compare (every boot looks like a fresh insert). So the diff is computed in
`toast_sync.py` *before* the CSV is overwritten (see above), and the app
imports `data/price_changes.json` into the `PriceHistory` table on every boot
(`_import_price_change_diffs` in `app/__init__.py`), deduped so a redeploy
doesn't double-import the same diff.

Staff see a "price changes need new labels" banner in the scanner UI
(polled every 2 minutes), open the review panel, and print or dismiss each
one (`GET/POST /api/price-changes*`). Nothing prints automatically.

**Known tradeoff:** because `price_changes.json` only ever holds the *latest*
sync's diffs, two syncs landing back-to-back before staff review the first
batch will overwrite it — a "miss." This is the accepted cost of staying on
the free tier without a persistent disk.

### 3. Scan → print (staff-facing)

`GET /api/lookup/<upc>` is SQLite-first (`CacheService`), with fuzzy-suggestion
fallback on a miss. `POST /api/print` renders the label (Pillow) and either
prints it directly (`local` print mode, single worker thread) or queues a
`PrintJob` row for the store bridge to claim (`remote` print mode — what
production uses, since a cloud box can't reach the store printer). Every job
is tagged with a `reason` (`NULL` = manual, `"price_change"` = queued from the
review panel) and browsable/reprintable from `GET /api/print-history`.

### 4. Print bridge (cloud → physical printer)

`scripts/print_bridge.py` runs on any always-on device on the store WiFi
(a Termux tablet in production). It polls `GET /api/bridge/jobs/next`,
downloads the pre-rendered raster for the claimed job, streams it to the
Brother QL-810W over port 9100, and reports completion. Its polling also
doubles as a keep-alive that stops the free Render dyno from sleeping. See
`docs/BRIDGE.md`.

## Quick start (local development)

```bash
cd spicetown-labels

# 1) Virtual environment (Python 3.12)
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 2) Configure (optional — sensible defaults exist)
cp .env.example .env          # edit if needed

# 3) Initialise the SQLite schema
python manage.py init-db

# 4) Verify the data provider is reachable
python manage.py provider-check        # -> provider=file healthy=True

# 5) Bulk-load the catalog into SQLite (also runs automatically on server boot)
python manage.py load                  # -> load complete: seen=... inserted=... ...

# 6) Run the dev server (auto-loads on startup + schedules nightly refresh)
python run.py                          # http://localhost:8080
```

Smoke-test the API:

```bash
curl localhost:8080/api/health
# {"status":"ok","provider":"file","db_ok":true,"product_count":...,"refresh_running":false,
#  "print_mode":"local","print_worker_alive":true,"print_queue_depth":0}

curl localhost:8080/api/lookup/711535509127     # {"found":true,"outcome":"hit",...}
curl localhost:8080/api/stats                   # cache + print-queue metrics
curl -X POST localhost:8080/api/refresh         # manual bulk refresh -> stats

# Print a label (enqueues; single worker renders + prints in local mode).
# wait=true blocks for the terminal status. variant auto-resolves to
# sale/clearance/standard from the product's current price flags.
curl -X POST localhost:8080/api/print \
  -H 'Content-Type: application/json' \
  -d '{"upc":"711535509127","copies":1,"wait":true}'
curl localhost:8080/api/print/1                 # poll a job's status

# Print history — every job ever queued, newest first; ?reason=price_change
# filters to price-review prints only.
curl 'localhost:8080/api/print-history?limit=20'

# Price-change review queue (populated from data/price_changes.json on boot,
# or by a live DB-diff during a continuous dev session):
curl localhost:8080/api/price-changes
curl -X POST localhost:8080/api/price-changes/print -H 'Content-Type: application/json' -d '{"ids":[1]}'
curl -X POST localhost:8080/api/price-changes/dismiss -H 'Content-Type: application/json' -d '{"ids":[2]}'

# Preview the label image WITHOUT printing (powers the scanner UI):
curl localhost:8080/api/preview/711535509127.png -o label.png

# Fuzzy search — unrecognized barcode? search by typed name or let a
# misread/transposed UPC suggest the intended product:
curl 'localhost:8080/api/search?q=turmric'        # by name (typo-tolerant)
curl 'localhost:8080/api/search?q=041196910148'   # by UPC (auto-detected)
# A 404 /api/lookup also returns a "suggestions" list automatically.
```

### Printing without hardware (dev / preview)

instead of a printer — perfect for the dev box or verifying layout:

```bash
STL_PRINT_TRANSPORT=file STL_PRINT_SPOOL_DIR=./spool python run.py
# every /api/print writes ./spool/label_<ts>_job<N>.png
```

### Test print — 29×62mm (DK-1209) landscape @ 123% scale

`scripts/test_print.py` renders a real label and (on a machine with the
printer) sends it via `lp` with your exact settings.

```bash
# Render only (no printer) — writes a preview + a print-ready (rotated) file:
python scripts/test_print.py --upc 711535509127 --outdir ./spool

# Print on a Mac with the printer attached:
python scripts/test_print.py --upc 711535509127 --print \
    --printer Brother_QL_810W --media 29x62mm --landscape --scaling 123
# equivalent manual command:
#   lp -d Brother_QL_810W -o media=29x62mm -o landscape -o scaling=123 file.png
```

To find the exact media/PageSize name your driver expects:
`lpoptions -p Brother_QL_810W -l | grep -i PageSize`. To make the *app* print
this way for every job, set `STL_LABEL_SIZE=29x62` and
`STL_CUPS_LP_OPTIONS=media=29x62mm,landscape,scaling=123` (scaling auto-disables
fit-to-page). **Note:** `-o landscape` rotates the page, so the print file is
pre-rotated to portrait — feed `label_29x62_print_rotated.png`, not the preview.

## Architecture notes

Every point below is implemented and exercised by the test suite.

- **SQLite is the primary lookup layer.** `/api/lookup/<upc>` goes through
  `CacheService`, which reads SQLite first. `Product.upc` is **indexed**
  (`ix_products_upc`) but **not unique** — shared barcodes are allowed, so
  logical identity is `(upc, name)`; a scan of a shared barcode surfaces a
  picker in the UI.
- **Cache TTL** is modeled on the row: `Product.is_fresh()` uses 24h for
  standard prices and **1h for `price_flagged` rows** (`CACHE_TTL_*`). A miss
  (absent OR stale) optionally refreshes that single UPC from the provider.
- **Bulk-load at startup + nightly cron**, never on per-scan demand. The loader
  pre-loads existing rows (one SELECT) and commits in batches so 10,000+
  products load with bounded memory/WAL.
- **Cache-miss monitoring** (`MissRateMonitor`): a sliding 5-minute window logs
  a throttled WARNING when the miss ratio exceeds **5%**.
- **Duplicate-(upc,name) detection**: exact duplicates in the incoming feed
  are logged and skipped (first occurrence wins) — same rule applied
  independently in `app/services/loader.py` (DB path) and
  `scripts/toast_sync.py` (CI sync path).
- **Suspicious price-change flagging**: a **>20%** delta logs a WARNING, appends
  a `PriceHistory` row, and sets `price_flagged=True` (→ 1h TTL). The flag
  auto-clears once the price stabilizes. This is separate from — and layered
  under — the price-change *review queue* described above.
- **Price-change review queue**: `PriceHistory.reviewed_at`/`label_printed`
  track staff triage of each detected price move. Seeded either by a live
  DB-diff during a continuous session (`loader.upsert_record`) or, on the
  free-tier ephemeral-disk deploy, by importing `data/price_changes.json` on
  boot (`_import_price_change_diffs`).
- **Print history**: every `PrintJob` (queue/local worker or remote bridge
  path) persists status transitions and a `reason` tag, so
  `GET /api/print-history` and its reprint action are just a read of that
  table — no separate log to keep in sync.
- **Token-bucket limiter** (`TokenBucket`, default 10 req/s, burst 20) is a
  process-wide singleton (`get_default_bucket`) shared by every external-call
  site. `ToastDataProvider` routes *all* traffic through it.
- **Exponential backoff + full jitter** (`backoff_retry`, `compute_backoff`)
  retries on 429/5xx (`RETRYABLE_STATUS`); an expired Toast OAuth token
  (401 mid-flight) is refreshed transparently and the call retried.
- **WAL mode** (`extensions.py`) lets the nightly refresh / print worker write
  while scans read. A process-wide lock (`bulk_load_guarded`) ensures the
  nightly refresh and a manual `/api/refresh` never run concurrently.
- **Two print modes** (`STL_PRINT_MODE`):
  - `local` — `POST /api/print` enqueues to an in-process `queue.Queue`; a
    single worker thread renders (Pillow) and drives the printer directly
    (jobs stay ordered, the QL is never driven concurrently). Bounded queue
    applies back-pressure (`503` when full); transient `PrinterError`s retry
    with backoff+jitter.
  - `remote` — what production uses (a cloud box can't reach the store
    printer). `POST /api/print` just writes a `PrintJob` row; the store-side
    bridge (`scripts/print_bridge.py`) polls `/api/bridge/jobs/next`, claims
    a job, downloads the pre-rendered raster, and drives the printer over the
    store WiFi. Stale claimed-but-undelivered jobs (`BRIDGE_STALE_SECONDS`)
    are automatically re-queued.
- **Pluggable printer transport** (`STL_PRINT_TRANSPORT`, local mode only):
  `cups` (`lp`), `brother_ql` (raster over USB/network), `file` (spool PNGs),
  `null` (tests/remote-mode safety net). Switching is config-only.
- **AI name auto-shortening** (`shorten_name`): a compact `short_name` is
  computed at load time (abbreviation map + filler-drop) so long names stay
  legible on a 62mm label; the renderer applies a width-aware fallback.
- **Fuzzy search** (`SearchService`, rapidfuzz): unrecognized barcodes are
  rescued by typed-name search or misread-UPC suggestions. It ranks over
  lightweight column rows (re-fetching only matches) and only runs on the rare
  not-found path, so it never touches the normal scan budget.

### Switching data providers (config-only)

```bash
# Local file (default) — what the deployed app runs; the catalog is kept in
# sync by the GitHub Action, so the app never needs Toast credentials.
STL_DATA_PROVIDER=file STL_PRODUCTS_FILE=./data/products.csv

# Toast POS directly (bypasses the CSV/GitHub sync entirely — used by
# scripts/toast_sync.py and available to the app itself if you want the
# scheduler talking to Toast in-process instead of via CI)
STL_DATA_PROVIDER=toast STL_TOAST_CLIENT_ID=… STL_TOAST_CLIENT_SECRET=… STL_TOAST_RESTAURANT_GUID=…
```

No calling code changes — `build_provider()` returns the right adapter.

## Printer setup

See `docs/BRIDGE.md` for the production remote-bridge setup (store tablet +
Brother QL-810W over WiFi). For **local** printing (`STL_PRINT_MODE=local`,
e.g. a Mac Mini running the whole stack in-store), set in `.env`:

1. **CUPS printer name** — `STL_CUPS_PRINTER_NAME=Brother_QL_810W`
   (find the exact queue name via `lpstat -p`).
2. **Label media** — `STL_LABEL_SIZE=62` (62mm continuous). For **die-cut**
   labels (e.g. `62x29`) set that value; the renderer already knows the pixel
   geometry for common QL media (`QL_MEDIA_PX`).
3. **Transport** — `STL_PRINT_TRANSPORT=cups` (default; uses the OS Brother
   driver via `lp`). Or `brother_ql` for direct raster over USB
   (`STL_PRINTER_BACKEND=pyusb`/`linux_kernel`, `STL_PRINTER_DEVICE=/dev/usb/lp0`)
   or network.
